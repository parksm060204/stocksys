## 독립성 및 변경 제약

1. 새로 읽고 판단한다. 이전 작업자가 “해결/통과”라고 보고한 내용을 사실로 가정하지 말고 구현과 테스트를 대조한다.
2. 애플리케이션 코드·기존 테스트·설정·의존성·AGENTS.md를 수정하지 않는다. 자동 수정 도구도 사용하지 않는다. 허용되는 영구 수정은 지정 결과 문서 생성과 HISTORY.md 끝에 실제 리뷰 결과 append뿐이다.
3. 기존 미커밋 `.codex/hooks.json`, `.codex/run-impeccable-hook.cjs`, `debug.log`를 건드리지 않는다. 사용자 작업을 reset/clean/stash/checkout하지 않는다. commit/push/deploy하지 않는다.
4. 재현은 별도 Node 프로세스의 메모리 DB나 검증된 임시 디렉터리에서 수행한다. 실제 `.data` 스냅샷·운영 DB·외부 계정을 변경하지 말고 환경변수 값이나 토큰을 출력하지 않는다. 기존 서버와 다른 에이전트를 종료하지 않는다.
5. AGENTS.md와 설치된 `node_modules/next/dist/docs/`의 관련 가이드를 준수한다. 테스트 실행으로 생긴 출력은 원래 파일과 혼동하지 않는다.

## 검토 범위

전체 파일 목록과 실행 진입점을 먼저 파악하고 실제로 읽은 범위를 기록한다. 다음 영역을 빠짐없이 점검하되 모든 파일 모든 줄을 검토하지 못했다면 그대로 명시한다.

- `app/api/**`: 세션/관리자 검증, 소유권, 공개 조회 개인정보, 입력 검증, 일반 주문/RPC/옵션/원자재/ETF/이벤트/상점/환전 경로의 우회 및 일관성.
- `lib/memoryDb/**`: 저장·복원, 전역 커밋 경계, 계좌/종목 잠금 순서 및 재진입, 중간 상태 혼입, rollback 소유 범위, 쓰기 실패·예외 경로, 스냅샷 호환 및 ID/시퀀스 영속성, 인덱스 일관성, 장기 상한.
- `lib/engine/**`, `lib/repositories/**`, `engine-server/src/**`: 실제 사용자/봇 실행 연결, 정산·수수료·잔액·재고·예약금, 자동 체결 저장과 실패 이후 상태, 주문 생명주기, 파생상품 만기, LP 부채, 재시작 충돌과 멱등성, 시뮬레이션 시간/PRNG 재개, 동시 거래.
- `lib/options/**`, `lib/commodities/**`, `lib/exchange/**`, `lib/shop/**`, `lib/events/**`: 금액 단위, 자산 종류, 계약 승수, 반올림/안전정수, 가격 우선순위, 누적 상대방 자금 검사, 청산 증거금 면제와 부분 체결·반전·중복 청산·예약 이관, 소유권과 중복 요청.
- `app/**` 및 클라이언트 훅: 실제 서버 데이터 연결, 옵션 계좌/월물/전량 취소·청산, ETF 호가/주문 결과, 인증 변화, 반복 요청/폴링, 가짜 성공, stale 상태, v2 공유 경로, 에러 처리, 서버 전용 모듈 누수.
- 설정·운영: 현재 사용 중인 구성, 프로덕션 경로, 프로세스/타이머 수명, 오류 전파와 실패 시 동작. 보관된 legacy 코드는 현재 실행과 연결될 때만 장애 근거로 삼는다.

## 특히 다시 검증할 불변식

- 이전 16개 항목을 각각 해결/미해결/부분 해결/미검증으로 판정한다. 번호별 실제 파일·근거를 기록한다.
- 커밋 게이트가 도입됐다는 사실만 보지 말고 모든 실제 쓰기 경로가 참여하는지, 잠금 대기 순서가 일관적인지, AsyncLocalStorage 재진입이 동시 자식 작업에 안전한지 확인한다.
- 엔진 저장 실패를 반환/로그하는 것과 커밋·롤백·재시작 시 장부가 일치하는 것을 구분한다. `COMMITTED`와 `PERSISTENCE_FAILED`가 동시에 반환되는 분기를 실제 의미에 맞게 평가한다.
- 워터마크는 메모리 상한 외에도 순서 역전·동시 종목 체결·실패 거래·누락 시퀀스·복원에서 미정산 거래를 정산된 것으로 오판하지 않아야 한다.
- 옵션 수수료·현금 검증은 동일 상대방이 여러 주문을 가진 경우 누적으로 검증되는지 확인한다.
- 원자재 reduce-only 면제는 청산 예약보다 신규 포지션이 먼저 체결되거나 부분체결/취소/재시작이 섞여도 과소 증거금이나 무담보 반전이 없어야 한다.
- 새 시드 데이터 생성이 기존 스냅샷 복원 시에도 필요한 미래 계약/ETF를 공급하는지, 기존 계약의 실제 만기를 임의 연장하지 않는지 확인한다.
- 테스트가 실제 프로덕션의 서비스/어댑터/콜백·잠금 구성을 재현하는지 확인한다. static string 검사나 좁은 성공 사례만으로 해결을 단정하지 않는다.

## 증거와 검증

보고서는 재현 가능한 버그를 심각도 순으로 제시한다. 각 항목에 P0/P1/P2/P3, 제목, 정확한 파일·좁은 라인 범위, 발생 조건, 관측 결과/기대 결과, 영향, 최소 재현 또는 코드 경로, 수정 방향을 포함한다. 이전 지적과 같은 문제라면 재발/잔존이라고 표시하고 중복 건수를 부풀리지 않는다. 추측은 확정 결함과 분리한다.

필요한 기존 검증을 격리 실행한다. 현재 소스를 읽은 뒤 안전성을 확인하고 선택한다.

- 루트 및 engine-server `tsc --noEmit --incremental false`
- `scripts/test-codex-review-16-fixes.ts`
- `scripts/test-review-fixes-verification.ts`, `scripts/test-followup-a-to-f.ts`
- 정산/동시성/재시작 관련 기존 테스트와 필요한 격리 재현

이전 검증을 전부 무의미하게 반복하지 말고, 검토 결론의 빈틈을 메우는 테스트를 수행한다. 프로덕션 빌드/브라우저/실제 OAuth/강제 재시작 실험을 하지 않았다면 미실행으로 명시한다. 실패 명령의 exit code와 에러를 숨기지 않는다.
