# 2026-11-20 전체 코드 리뷰 확정 결함 수정

## 사용자 요청과 작업 범위
사용자가 최신 전체 코드 리뷰를 수정하되 코딩은 워커가 수행하도록 요청했다. 당신은 Orca Antigravity Hydrogen High 구현 워커다. 현재 작업 디렉터리 전체 작업본에서 `docs/full-code-review-2026-11-20-findings.md`를 먼저 읽고 확정 결함 F-20261120-01~10 전부를 수정하고 검증한다. 추측 SU-01~05는 확정 결함 수정에 필수인 경우만 다루고, 별도 정책 변경이나 원격 운영 환경 접근은 하지 않는다. 사용자에게 다시 허락을 묻지 말고 합리적 구현 판단으로 완료한다.

## 필수 제약
- 현재 작업 트리에는 이전 세션의 많은 수정 및 신규 파일이 있다. 시작 시 git status와 관련 diff를 읽고 보존한다. reset, checkout 덮어쓰기, clean, stash, 기존 변경 삭제 금지.
- 모든 애플리케이션/테스트 코딩은 당신이 수행한다. 코디네이터는 문서 작성 및 검증과 리뷰를 담당한다.
- AGENTS.md를 준수한다. Next.js 코드를 쓰기 전에 node_modules/next/dist/docs/ 관련 가이드를 읽는다. UI 수정에는 적용 가능한 impeccable 스킬을 읽고 기능 교정 위주로 범위를 제한한다. 여러 TSX 수정 후 vercel:react-best-practices 체크리스트도 적용한다.
- 실제 .data, snapshot, 운영 DB, 환경변수 비밀을 변경하거나 출력하지 않는다. 모든 동적 테스트는 별도 임시 STOCKSYS_DATA_DIR 및 필요한 격리 인메모리 저장소를 사용한다. 프로덕션 서비스 시작이나 원격 DB 변경 금지.
- commit/push/deploy 금지. .codex 설정 및 AGENTS.md 변경 금지.
- 정산 변경은 계좌/종목 락, 커밋 게이트, rollback, 중복 지급 방지를 유지한다. 뉴스 권한 수정은 비구독 RUMOR 원문이 SSR/클라이언트 응답에 실리지 않음을 검증한다.

## 구현과 수용 기준
1. F01: 채권 지급 주기/기간 키를 일관되게 만들어 분기당 한 번만 쿠폰 지급. 이미 쿠폰 지급한 기간 내 만기에는 원금 상환이 성공하고 중복 쿠폰이 없어야 한다. 실패를 무시하지 않는다. 기존 저장 데이터 지급 키와의 호환 및 테스트의 clock 일치도 확인한다.
2. F02: standalone 활성 틱에서 옵션/채권 만기 정산을 락/커밋/영속 경계와 맞춰 실행한다. 수동 서비스 호출만으로 완료 판정하지 말고 실제 tick 경로를 검증한다.
3. F03: 실제 사용자 주문을 보호하면서 종료/만료 봇 및 LP 주문을 유한하게 정리하고 인덱스도 정합하게 유지한다. acc_* 문자열만으로 실제 사용자 권한을 넓히지 않는다.
4. F04: V1/V2 종목 상세의 미지원 or 조회 크래시 해결, 서버 세션/프로필을 통한 뉴스 권한 적용, title 필드 호환. 익명/미구독/구독 사용자 응답 검증.
5. F05: 해외주식/USD ETF 0.01 틱, 국내주식 KRX 틱, 채권만 채권 클램프. 저장소 주문 가격을 재정렬해 ORDER_PRICE_MISMATCH를 일으키지 않도록 실제 매칭/정산 검증.
6. F06: 실제 원자재 API depth/spread 형식으로 호가 잔량/스프레드 표시. 빈 호가와 null에도 NaN 없음.
7. F07: side 기반 숏 표시와 매수 청산 증거금 계산 교정. 부분청산 및 반대방향 초과 주문도 서버 규칙과 정합.
8. F08: 관리자 거래 동결/LP 무한 유동성 및 주식/채권 시나리오의 허위 동작 제거. 안전하게 구현 가능한 서버/엔진 연동을 구현하거나, 보고서 허용 방향대로 미지원 컨트롤 비활성화와 명확한 안내, API에서도 비지원 시나리오 거부. UI만 제한하고 API 우회 허용하지 않는다. 원자재 시나리오 정상 동작 보존.
9. F09: USD ETF의 V1/V2 가격, 등락폭, 시고저, 체결, 거래대금에 공용 currency/ticker 규칙을 일관 적용. 국내 ETF KRW 유지.
10. F10: 옵션 비율 수량에 서버와 같은 예약 수수료를 적용. float 경계와 기존 예약 금액/보유 매도 규칙을 확인해 100% 주문이 잔액 경계에서 거부되지 않도록 한다.

## 검증 및 완료 보고
- 금전/권한/틱/정산/정리에는 의미 있는 회귀 테스트를 추가한다. 단순 소스 문자열 포함 검사를 실제 동작 검증의 대체로 삼지 않는다.
- 루트 및 engine-server TypeScript, lint, production build, 신규 회귀, 기존 test-full-review-2026-11-19-fixes.ts, test-reachable-security-fixes.ts 및 영향받는 정산/주문/동시성 테스트를 실행한다. 실패하면 관련 원인 수정 후 재검증한다. 넓은 반복 검증은 필요할 때만 한다.
- 최신 production build로 가능한 격리 HTTP/SSR 및 UI smoke를 검증한다. 브라우저는 Orca browser 가이드에 따른다. 실제 OAuth는 필요 없으며 미실측 한계는 명시한다.
- `docs/full-code-review-2026-11-20-fix-results.md`에 항목별 수정 파일, 핵심 동작, 테스트 명령/exit code, 제약과 미해결 사항을 기록한다. 원본 리뷰 보고서는 유지한다.
- HISTORY.md 끝에 실제 구현 결과를 타임스탬프 포함 한국어 UTF-8로 추가한다.
- 완료 시 worker_done으로 F01~F10 각각 상태, 테스트 근거, 보고서 경로, 남은 한계를 보고한다. 모든 결함 수정이 목표이며 비영 exit를 단순 수집만 하고 성공으로 보고하지 않는다. 해결할 수 없는 장애는 구체적인 증거와 질문을 orchestration ask로 코디네이터에게 보낸다.
