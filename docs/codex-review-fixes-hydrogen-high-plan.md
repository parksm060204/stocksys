## 실행 규칙

2. 수정 순서는 자산 경계 → 커밋/롤백 동시성 → 금액/예약 불변식 → 재시작/저장 상한 → 나머지 서비스/UI다.
3. 보고서의 해결 방향은 제안이다. 실제 구조를 확인해 올바른 해결책을 구현하되 16개 항목 각각의 해결 여부를 설명한다.

5. 운영 데이터, 실제 .data 스냅샷, 비밀 환경 변수 값을 수정/삭제/출력하지 않는다. 재현과 검증은 격리 메모리 DB 또는 임시 디렉터리에서 수행한다. 기존 개발 서버나 다른 에이전트를 종료하지 않는다.
6. commit/push/deploy 및 외부 서비스 변경은 수행하지 않는다. 완료 시 변경을 현재 작업 트리에 남긴다.
7. 여러 TSX 컴포넌트를 수정하면 `C:/Users/abcde/.codex/plugins/cache/openai-curated-remote/vercel/0.54.1/skills/react-best-practices/SKILL.md`를 읽고 관련 체크리스트를 적용한다. 사용자가 요청하지 않은 외관 재설계는 하지 않는다.
8. 애매한 구현 선택은 합리적으로 결정해 진행한다. 작업 범위상 해결할 수 없는 실제 차단 사유만 coordinator에게 orchestration ask로 전달한다.

## 항목별 필수 완료 조건

1. 일반 주식 주문 API와 RPC에서 옵션 ID/미등록 자산이 주식 정산 경로로 들어가지 못하게 한다. 승수·자격·만기 우회 재현을 차단한다.
2. 전역 저장 스냅샷에 다른 트랜잭션의 미확정 상태가 섞이지 않게 한다. 상태 변경부터 저장 성공 또는 실패 롤백까지 일관된 경계를 설계하고 자동 저장도 동일 정책에 참여시킨다. 저장 대기 중 다른 계좌의 성공 스냅샷이 실패한 거래를 담는지 검사한다.
3. 원자재 틱 실패 롤백이 동시 환전/상점/주식/새 원자재 주문을 덮어쓰지 않게 한다. 계좌 잠금 순서와 전역 커밋 경계 간 교착을 피하고 틱이 소유한 상태의 복원 범위를 정확히 한다. 실패 틱의 봇 자산/체결 이력/가격/시계도 함께 확인한다.
4. 소액 환전 왕복으로 가치가 생성되지 않게 한다. 기본 USD 환율에서 7 KRW → 0.01 USD → 14 KRW 재현을 차단하고 통화별 최소 단위와 반올림 정책을 정의한다.
5. 주식/옵션/환전/상점/원자재가 계약별 승수와 수수료를 반영한 공용 가용 현금 계산을 사용하게 한다. 이미 차감한 원자재 증거금을 중복 차감하지 않는다.
6. engine-server의 복원 후 실행 ID/주문 ID/체결 ID가 충돌하지 않게 한다. 운영 재시작 정책과 시드 결정론적 테스트 요구를 모두 유지한다.
7. 정산 원장의 멱등성 보존을 유지하면서 실제 사용 ID의 메모리 및 스냅샷 증가를 제한한다. evictedCustomTradeIds를 단순 삭제해 재실행을 허용하지 않는다.
8. 자동 체결의 내구성 경계를 연결하고 저장 실패가 무시되지 않게 한다. Next.js 내부 엔진과 별도 engine-server 경로를 모두 확인한다.
9. 옵션 매칭에서 사용자 대기 주문과 LP 호가를 함께 가격 우선 비교한다. LP ask 10, 사용자 ask 20이면 시장가 매수는 10을 선택해야 한다.
10. 원자재 증거금/실현손익 환율이 `rate_to_krw` 등 권위 스키마를 일관되게 사용하게 한다. 기본 DB USD 1380을 1350으로 읽는 문제를 고친다.
11. 기존 원자재 포지션을 줄이는 주문에 불필요한 신규 진입 증거금을 요구하지 않게 한다. 중복 청산 주문 및 반대 포지션 전환에 필요한 증거금은 안전하게 검증한다.
12. 옵션 계좌 패널을 실제 본인 주문/보유량/거래 데이터와 연결하고 전체 취소/청산을 실제 서버 동작으로 구현한다. 샘플 계좌나 alert만으로 성공을 표시하지 않는다.
13. 옵션 체인의 월물/행사가/시세를 실제 DB 계약 데이터와 연결하고 선택 계약 ID와 티커를 일치시킨다. 만기된 고정 202608 데이터에 의존하지 않는다.
14. ETF 거래를 권위 서버 주문 API에 연결하고 성공 응답 후 실제 자산을 다시 조회한다. 403 오류를 무시한 가짜 체결 알림을 제거한다.
15. 랜덤 이벤트 선택을 서버 권위의 비용 차감/효과 부여/해결 상태 갱신에 연결한다. 세션 소유권, 서버 선택지/가격, 중복 요청을 검증한다.
16. 인증/SSR 데이터 헬퍼/market-flow/관리자 경로의 복원 대기를 통일한다. OAuth 세션 콜백과 준비 상태 초기화 사이 순환 호출 및 교착이 생기지 않게 DB 준비와 엔진 기동을 필요에 따라 분리한다.
