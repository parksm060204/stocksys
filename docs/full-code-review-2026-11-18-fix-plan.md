# 전체 코드 리뷰 25건 수정 및 검증 지시

## 사용자 요청과 목표

사용자가 전체 코드 리뷰 결과를 보고 워커에게 수정을 명령했다. `docs/full-code-review-2026-11-18-findings.md` F1~F25 전체를 처리한다. 기존 사용자 지정 AGY Hydrogen high 설정으로 수행한다. 현재 공유 워크트리의 기존 미커밋 개선 코드와 사용자 변경을 보존한다. 보고서의 심각도·수정안은 재검증 대상이며 잘못된 진단은 실제 호출 경로와 반증을 기록하고 종결한다. 이전 테스트 통과를 근거로 결함을 무시하지 않는다.

## 준수사항

- AGENTS.md를 읽고 Next 코드를 쓰기 전 설치된 `node_modules/next/dist/docs/` 관련 가이드를 확인한다. 여러 TSX 수정 후 `vercel:react-best-practices` 스킬을 적용한다.
- 변경 가능한 범위는 각 결함 해결에 필요한 애플리케이션/엔진/테스트 및 문서. `.codex/hooks.json`, `.codex/run-impeccable-hook.cjs`, debug.log 등 기존 사용자 변경은 건드리지 않는다. git reset/checkout/clean이나 커밋·푸시는 하지 않는다.
- 운영 .data/외부 DB/실 OAuth를 변경하지 않는다. 환경변수·토큰·비밀값 전체를 출력하지 않는다. 테스트는 임시 STOCKSYS_DATA_DIR 또는 격리 MemoryDatabase에서 실행한다.

## 반드시 다룰 결함과 구현 원칙

1. **F1/F2 단위**: 지수 옵션의 지수·행사가·승수 및 채권 쿠폰 % 단위를 생성/조회/정산/UI 전 경로에서 일치시킨다. IDX와 개별주식 옵션을 명확히 구분한다. 과거 계약의 행사가/만기를 임의로 바꿔 보유자의 권리를 변경하지 않는다. 구형 스냅샷을 위한 명시적 마이그레이션/검증 정책과 불일치 계약 정산 차단을 마련한다. 쿠폰 엔진에서 전달한 금액 및 repository의 권위 계산도 함께 일치시키고 100배 지급/상환 거부를 회귀 검증한다.
2. **F3/F19 원자성**: 신규 주문 배치 실패 때 ghost order가 map/index 어디에도 남지 않게 한다. outer tick rollback이 이미 보호하는 경로와 repository 자체 계약을 구분한다. profile rollback은 추가된 키까지 정확히 제거하고 객체 참조 유지 요구·다른 계좌 동시 변경 보호를 검증한다.
3. **F4 원자재 손실 정책**: 유지증거금 평가와 청산, 갭 손실 및 다른 자산 예약금 침범을 처리한다. 단순 cash=0 clamp로 손실을 삭제하거나 허위 자금을 만들지 않는다. 부족분은 명시적인 부채/청산 상태 등 회계적으로 일치하는 장부로 처리하고 신규 위험 주문을 제한한다. 저장 실패·재시도·재시작 후에도 일관된 정책을 유지한다. 상품별 승수/환율과 양방향·부분청산·취소를 함께 점검한다.
4. **F5~F7/F11 봇 및 시뮬레이션**: 보고서의 보유 키 ':' 불일치, USD 환율/NAV/예산 및 틱 누락, 비-LP 주문 표기, 빈 orderBook와 ordersToCancel 미소비를 실제 활성 경로에서 수정한다. is_lp 검증을 약화해 우회하지 말고 participant metadata와 주문 생성 의도를 정렬한다. LP 갱신 upsert/캡 원칙과 소음/중복 주문 억제를 유지한다.
5. **F8~F10/F12/F13/F18 화면·계약**: V2 종목 필드 정규화 및 가격 폴링/cleanup, OptionsPanel 요청 qty와 응답 order.filledQty, 실제 근월/차월 동일 유형·행사가 롤오버 선별과 첫 다리 부분체결 후 처리, 미체결 종목/통화 조인, 채권 상세 주문의 지원 API/상태, 옵션 ATM과 실 기초지수를 일치시킨다. UI를 API와 같은 payload로 실행 검증한다. 미구현 기능은 실제 동작하는 것처럼 노출하지 않는다.
6. **F14~F17 권한/기능**: 관리자 시나리오 수치 검증·락·영속화·실패복구를 적용한다. 관리자 UI 인증을 바로잡고 신규 상장/이벤트의 실제 서버 관리자 API를 연결한다. market-flow의 공개 정보와 내부 비공개 정보를 구분하여 내부 값은 서버 권한 검증 후 제공한다. 유료 아이템/보상 효과를 수수료 예약·정산·기능 권한에 실제 반영하고, 구현할 수 없는 상품은 과금 중단 및 기존 구매 권리/환불 정책을 기록한다. 무조건 무료 이득이나 중복 환불을 만들지 않는다.
7. **F20/F21 기록 관리**: 임의 FIFO로 과거 정산키를 잊어 중복 지급을 허용하지 않는다. 상환/커스텀 키의 실제 생성자와 유한 카탈로그 여부를 조사하여 필요한 압축·보존 정책을 설계한다. 유효한 키가 미정산으로 되돌아가는 경우, epoch와 시간순 역전도 테스트한다. 자전거래 취소/만료 상태를 구분한다.
8. **F22~F25 경로 및 검사**: 404 링크/종목 검색/WTI 충격 ID를 실제 기능과 연결한다. 현 프로젝트에서 사용하지 않는 vm-db 경로는 활성 경로를 확인하여 문서를 정확히 갱신한다. lint 오류 5건과 실패 테스트 3건을 수정하되, 정상 안전 검증을 제거/skip하거나 assert를 단순 완화하지 않는다. stale fixture는 새 계약에 맞추고 새 불변식도 검증한다. 기존 경고는 새로 생긴 오류와 구분하며 불필요한 전면 정리는 하지 않는다.

## 검증과 완료 보고

- 독립 재현 F1~F7/F10/F19, 금전·락·롤백·멱등성 수정에 의미 있는 회귀 테스트를 남긴다. 수동 비정상 fixture만 검증하지 말고 사용자/봇 실제 API 도달 경로를 함께 검증한다.
- 루트/engine tsc, npm run lint, npm run build, 이전 리뷰의 37개 테스트(실패 3종 포함), 새 회귀 테스트를 실행한다. 적절한 로컬 HTTP/브라우저 검증으로 V2 표시/시세·옵션 주문·청산·취소·관리자·상점·검색을 확인한다. 실브라우저 사용 시 Orca 브라우저 스킬을 읽는다. 검증 실패를 방치한 채 완료라 보고하지 않는다.
- 빌드/테스트를 백그라운드로 시작한 경우 결과를 회수하고 원인을 해결한다. 기다리고 있다는 문장만 남기고 턴을 끝내지 않는다.
- 결과는 `docs/full-code-review-2026-11-18-fix-results.md`에 F1~F25 각각 해결/부분해결/반증/미해결, 파일·행, 정책 변경, 테스트 명령/exit, 구형 데이터 호환성과 미검증 영역을 기록한다. 링크는 `/C:/.../file.ts:행` 형식을 쓴다.
- HISTORY.md 끝에 타임스탬프 및 실제 변경/검증 요약을 append한다.
- 반드시 worker_done으로 최종 결과를 보고한다. 해결 건수와 반증/미해결 건수를 나누고, 필수 검증 실패 또는 미해결 문제가 있으면 성공으로 뭉뚱그리지 않는다. 보고서는 실제 검증만 근거로 작성한다.
