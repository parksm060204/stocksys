# 독립 재리뷰 발견 사항 전체 수정

## 목표와 작업 환경

사용자가 `docs/post-fix-full-review-findings.md`의 발견 사항을 수정하도록 요청했다. 해당 보고서의 P1 2건, P2 6그룹, P3 1그룹 및 각 그룹의 하위 결함을 모두 처리한다. AGY Antigravity Hydrogen high 워커로 구현과 검증을 수행한다. 현재 공유 워크트리에서 작업한다. 보고서 자체가 모든 수정 방향을 강제하는 것은 아니므로 실제 코드를 확인하여 안전한 구현을 선택한다.

먼저 AGENTS.md와 보고서를 읽고, Next 관련 코드를 쓰기 전 설치된 `node_modules/next/dist/docs/` 가이드를 읽는다. 여러 TSX 수정 후 제공된 `vercel:react-best-practices` 스킬을 적용한다. 기존 사용자 변경(.codex/hooks.json, .codex/run-impeccable-hook.cjs, debug.log), HISTORY.md와 기존 리뷰 문서를 보존한다. 비밀값이나 환경변수 전체를 출력하지 않는다. 실제 운영 DB/서비스를 조작하지 않는다. 커밋/푸시는 이번 작업에 포함하지 않는다.

## 필수 수정 범위

1. 옵션 매수 상대방의 수수료와 계좌별 누적 체결 필요 현금을 검증한다. 다건 주문 예약 및 부분 체결과 일치시키고, 부족한 상대방 처리 시 전체 자산 상태가 원자적으로 유지되게 한다. 주식/ETF 사전 매수 검증과 예약 현금에도 실제 정산 수수료 정책을 일관되게 적용한다.
2. engine-server MarketEngine.tick의 저장 실패 시 DB 및 런타임 전체 상태를 복원하고 미커밋 결과를 반환하도록 저장/커밋 경계를 수정한다. 이미 공개된 후처리와 혼동하지 말고 기존 post-commit 의미 및 재시도 중복 방지를 점검한다. 옵션 만기, 채권 쿠폰 등 거래 없는 영구 자산 변경도 저장한다. 불필요한 디스크/WAL 증가를 피한다.
3. 오래된 스냅샷 복원 시 누락 ETF와 유효한 미래 옵션 월물을 비파괴 보충한다. 과거 계약의 만기나 기존 잔고/주문/가격을 임의 변경하지 않는다. 트랜잭션 롤백용 importSnapshot과 부팅 마이그레이션의 의미를 구분하여 롤백 시 신규 상태가 생기지 않게 한다.
4. 정산 기록을 삽입 순서가 뒤집혀도 미처리 거래를 기처리로 오인하지 않게 압축한다. opt_settle/bond ID도 무한 누적하지 않으면서 재시작·재실행 중복 지급 방지를 보장한다. 단순 Set 잘라내기로 중복 정산을 허용하지 않는다. 순번 공백 및 epoch 수명도 고려한다.
5. 미체결 주문 일괄 취소 필터를 API와 맞추고 소유권 검증, 계좌 잠금, 영속화 및 원자성을 보장한다.
6. 보고서 P2-5의 모든 UI/서버 단절을 수정한다: USD 종목/ETF의 표시·정산 통화를 일관되게 하고 기존 KRW 현금과 통화 자산 의미를 보존한다. 환율은 서버 권위 데이터로 처리하고 관련 주문/예약/평가 경로를 점검한다. ETF 시세는 서버 데이터에 연결한다. 원자재 reduce-only 청산 UI, 동적 환율, 증거금 반환이 원자적인 취소 API와 전용 미체결 패널을 구현한다. 마이페이지에서 옵션 이름/승수/평가를 올바르게 표시한다. 구형 OptionsPanel의 없는 RPC를 실제 지원 API에 연결하며 다리별 부분 성공을 성공한 콤보로 보고하지 않는다. HTTP RPC가 구체적인 JSON 오류를 보존한다.
7. P2-6 모든 결함 수정: 원자재 reconcile은 공유 in-flight Promise를 기다리게 하고 실패 후 재시도 가능하게 한다. 원자재 틱 가격을 DB와 일치시키고 저장 경계를 보장한다. 주문 삭제 보조 인덱스를 정리한다. 주기적 trim을 커밋/잠금 경계 안으로 넣는다. profiles SELECT에서 잠금 없는 상태 변경을 제거하거나 안전한 쓰기 경로로 옮긴다. 잠금 순서/교착을 점검한다.
8. premium_news 미존재 조회를 실제 뉴스/구독 데이터와 연결한다. 구독 권한을 서버에서도 검증한다. test-route-handlers-e2e.ts의 독립 실행 실패를 실제 경로를 검증하는 유효한 테스트로 수정한다.

## 검증과 완료 기준

- 임시 STOCKSYS_DATA_DIR와 격리 DB에서만 테스트한다. 운영 .data를 훼손하지 않는다.
- 금전, 동시성, 영속성 결함에는 실제 실패 조건과 불변식을 검증하는 회귀 테스트를 추가한다. 테스트의 assert 삭제나 기대값 약화로 통과시키지 않는다. 기존 COMMITTED+PERSISTENCE_FAILED 기대가 잘못됐다면 새 계약의 복원 불변식을 함께 검증하도록 변경한다.
- 루트/engine 타입 검사, 기존 16건 회귀/후속/Phase1~4 관련 테스트, 수정한 라우트 E2E 및 Next 프로덕션 빌드를 실행한다. 테스트 중 실패하면 원인을 해결하며 미해결이면 완료로 보고하지 않는다.
- 가능하면 로컬 HTTP 및 브라우저에서 일괄 취소, 원자재 청산/취소, ETF 실제 시세·주문, 옵션 계좌 평가, 뉴스 구독 흐름을 확인한다. 실제 OAuth나 운영 장애 실험 등 수행하지 못한 검증은 명시한다. 새 테스트가 서로 다른 통화, 부분 체결/누적 체결, 저장 실패 후 재시도, 기존 스냅샷 복원과 롤백 차이를 다루게 한다.
- HISTORY.md 끝에 실제 변경과 검증 결과를 규정 형식으로 추가한다.
- `docs/post-fix-review-remediation-results.md`에 각 P1/P2/P3 하위 항목별 변경 파일·행, 수정 내용, 실제 검증 명령/exit code, 미검증·잔여 사항을 기록한다. 그룹 단위로 뭉뚱그려 모두 해결했다고 주장하지 않는다. 완료 보고(worker_done)에 해당 문서 경로, 해결/미해결 수, 검증 결과와 위험을 포함한다.
- 비영(0이 아닌) 필수 검증 exit나 미해결 필수 결함은 task 실패 또는 부분완료로 정확히 보고한다. 이 작업은 리뷰에 그치지 않고 구현 완료가 목적이다.
