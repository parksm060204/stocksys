# 현재 전체 코드 독립 리뷰

## 요청과 산출물

사용자는 현재 전체 코드를 리뷰하여 문제점을 찾도록 요청했다. 기존에 지정한 AGY Antigravity / gemini-4-hydrogen-high / high로 독립 재검토한다. 현재 HEAD뿐 아니라 아직 커밋되지 않은 수정과 신규 파일도 리뷰 대상이다. 이전 수정 워커의 성공 주장이나 테스트 통과를 정답으로 가정하지 않는다. 이전 보고서는 맥락/반례 후보로만 사용한다.

리뷰 전용 작업이다. 애플리케이션, 테스트, 설정, 사용자 변경을 수정하거나 커밋/푸시하지 않는다. 허용 산출물은 `docs/full-code-review-2026-11-18-findings.md` 및 AGENTS.md 형식에 따른 HISTORY.md 끝 추가뿐이다. 재현 코드는 임시 파일/격리 프로세스에서 실행할 수 있으나 운영 .data나 운영 DB에 접근/변경하지 않는다. 비밀값이나 환경변수 전체를 출력하지 않는다.

## 범위 및 핵심 질문

- 먼저 AGENTS.md, git status/diff, 프로젝트 소스 파일 목록을 읽어 구조와 실제 활성 경로를 파악한다. 관련 Next 동작은 설치된 node_modules/next/dist/docs에서 확인한다.
- API 및 인증/인가: 모든 쓰기/RPC/범용 DB 경로와 공개 조회의 세션·소유권·관리자/구독 경계, 필터 우회, 민감정보 노출, 숫자/문자열 입력 검증, auth callback 장애 처리. 원격 SQL/RLS 정책과 로컬 메모리 경로의 권한 차이도 점검.
- 금전·정산: 일반주식/ETF/옵션/원자재/채권/환전/상점/랜덤 이벤트 전체의 수수료·통화·승수·예약·수량·부분 체결·누적 검증. 양쪽 계좌 및 봇 장부, 다른 자산 동시 주문, USD 호가와 KRW 잔고/평가의 실제 활성 경로 일관성.
- 동시성·내구성: 계좌/종목/엔진락과 커밋 게이트 순서, 재진입, 다른 거래를 덮는 전체 snapshot rollback, 틱 내 공개 이벤트 시점, 저장 실패/재시도, 실제 부팅 restore 및 마이그레이션과 rollback 분리, 런타임/봇/PRNG 상태 포함 여부. 여러 실행 모드(local standalone, agentManager, engine-server)마다 비교한다.
- 정산 멱등성·상한: interval/watermark의 순서 역전·공백·epoch 재시작/복원·오래된 ID·옵션 만기/채권 쿠폰/상환 재정산 차단. 아직 실제 미처리 ID가 처리된 것으로 판정되거나 잊은 키가 중복지급되는 경로, 사라지지 않는 메모리/디스크 누적, trade/history/order caps와 인덱스 정합성.
- 프론트엔드: 주요 페이지와 v2, 공용 패널, hooks의 데이터/API 연결·폴링 경쟁·cleanup·하드코딩 시세/통화·취소/청산/롤오버·옵션 마이페이지·구독 뉴스의 실제 사용 경로. 기능 실패를 성공 알림으로 보고하는 경우.
- 운영 및 배포: 실제 사용 설정/서버·스키마·Docker/WAL/log rotation·환경변수 fallback과 프로세스 종료, startup readiness, 저장 형식 호환성. 문서에만 있는 비활성 경로의 문제는 활성 여부를 명시한다.
- 이전 리뷰에서 읽지 못한 구간(정산 repository 앞부분, agentManager 중반, 개별 bot 구현, v2 컴포넌트)도 포함해 점검한다. 모든 파일을 읽었다고 과장하지 말고 범위표에 실제 읽은 부분/미검토 영역을 구체적으로 남긴다.

## 증거 및 보고 기준

- 발견 사항은 독립적인 결함마다 하나씩 번호를 붙인다. 서로 다른 수정이 필요한 5가지 결함을 한 그룹에 묶어 건수를 줄이지 않는다. 증거 없는 잠재 우려/취향/대규모 재설계 제안은 확정 findings에 섞지 않는다.
- 각 finding: P0/P1/P2/P3, 짧은 제목, 실제 파일/좁은 행 범위, 발생 입력/조건 및 호출 경로, 관측/기대 결과, 사용자 영향, 최소 수정 방향, 검증 방법과 재현 성공 여부. 실제 사용자/API로 도달 가능한 상태인지 명시하고 수동으로 만든 비정상 fixture만 재현 가능하면 그 한계를 분명히 쓴다.
- 금전/동시성/영속성 주요 의심은 격리 MemoryDatabase 또는 임시 STOCKSYS_DATA_DIR에서 실행 가능한 반례로 확인한다. 저수준 불변식 반례와 실제 엔드포인트 도달성은 구분한다. 기존 테스트가 통과해도 새 반례를 덮는지 직접 확인한다.
- 필요한 타입 검사 및 회귀 테스트를 실행하되 리뷰 자체가 테스트 실패 수정을 허용하지 않는다. 실패 명령/exit/원인을 그대로 기록한다. 프로덕션 빌드나 브라우저/OAuth/원격 DB 등을 실행하지 않았으면 명시한다. 테스트 실패를 기록하는 것은 리뷰 작업 실패가 아니다.
- 마지막으로 이전 `docs/post-fix-review-remediation-results.md`의 해결 주장을 독립 검증하여 해결/잔존/검증불가를 기록하되, 새 finding과 중복 계산하지 않는다.
- 문서 링크는 file:/// 대신 `/C:/Users/abcde/Desktop/웹소설/stock-sys/...:행` 형식의 절대 로컬 Markdown 링크로 작성한다.
- HISTORY.md에 실제 리뷰 수행과 결과를 추가하고 반드시 worker_done으로 보고한다. 완료 보고에는 finding 심각도별 건수, 가장 중요한 문제, 보고서 경로, 실행한 검증 결과, 범위 한계를 포함한다. 실행 중 검증을 시작했다는 말만 하고 턴을 끝내지 말고 결과를 회수한 뒤 완료 보고한다.
