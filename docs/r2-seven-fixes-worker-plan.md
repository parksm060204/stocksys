# 최신 재리뷰 R2-01~07 전체 수정

## 사용자 요청 및 정확한 대상
사용자가 최신 코드 리뷰에서 발견한 문제들을 해결하라고 요청했다. 정확한 수정 대상은 `docs/full-code-review-2026-11-20-rereview-findings.md`의 **R2-01~07(P1 5건, P2 2건)**이다. 이전 F01~10/AR01~04/TopBar는 이미 수정되어 있다. 코디네이터의 이전 표가 이 오래된 항목을 잘못 묶었으므로 해당 표를 작업 범위로 삼지 않는다. 이 문서와 최신 R2 보고서를 기준으로 일곱 결함 모두를 구현·검증한다.

코딩은 사용자 선호대로 Orca Antigravity Hydrogen High 워커인 당신이 전담한다. 현재 작업본에서 수정하고 worker_done으로 코디네이터에게 결과를 돌려준다.

## 공통 제약
- AGENTS.md, 최신 보고서, 관련 소스 및 git diff부터 확인한다. 수많은 기존 미커밋/신규 파일을 보존한다. reset/clean/checkout 덮어쓰기/stash/commit/push/deploy 금지. .codex 설정이나 AGENTS.md 변경 금지.
- Next.js 코드 수정 전 설치된 node_modules/next/dist/docs 관련 가이드를 읽는다. UI 수정에는 impeccable harden 지침 및 여러 TSX 수정 시 react-best-practices를 적용하되 시각적 재설계 없이 기능 교정에 집중한다.
- 운영 .data·스냅샷·실계정 OAuth·원격 DB를 수정/출력하거나 운영 서버를 재시작하지 않는다. 모든 검증은 임시 STOCKSYS_DATA_DIR / ENGINE_SERVER_DATA_DIR 및 별도 인메모리 DB를 사용한다. 빌드 산출물 기동 역시 임시 경로와 전용 미사용 포트로 수행하고 본인이 시작한 프로세스만 종료한다.
- 계좌/종목/원자재 tickLock/commitGate의 락 순서 및 재진입 제약을 지킨다. 영속 저장 실패 및 throw에도 현금·보유·주문·예약·권한·런타임을 원자적으로 복구한다.
- 모든 제품/테스트 코드 구현은 당신이 한다. 명확한 루틴 선택은 사용자 확인 없이 완료하고, 막힌 조건만 증거와 함께 orchestration ask로 보고한다.

## 수용 기준

### R2-01 시장 초기화 후 원자재 구주문 반복 틱 실패
- DB와 관련 런타임이 같은 reset 세대임을 식별하도록 reset version/epoch 또는 동등하게 견고한 방식을 적용한다. 같은 DB 객체라는 이유만으로 reconcile을 건너뛰지 않는다.
- 실제 관리자 reset 및 standalone reset 경로에서 원자재 오더북·봇 자산·예약·시퀀스가 일관되게 초기화되며, 원자재 tick/주문과 reset이 경합해 옛 주문을 되살리지 않도록 한다. 기본 시드 재생성/스냅샷 import/rollback의 세대 의미를 구분하고 기존 정상 restart 복원은 깨지지 않게 한다.
- 기본 50봇과 실제 원자재 주문 제출→reset→동일 DB reconcile→두 번 이상 stepTickAsync가 모두 성공하고 구주문·예약이 재등장하지 않음을 검증한다. 초기화 중 영속 실패도 가능한 경계에서 복구한다.

### R2-02 상속 속성 상품ID 현금 NaN 손상
- SHOP_PRODUCTS의 own-property allowlist/Map으로 __proto__, constructor, toString 등 비상품 ID를 변경 전에 거절한다. 상품/금액/기간의 타입·유한값·허용 범위를 검증한다.
- 구매 처리 전후 예외/저장 실패 모두 현금과 권한 원본이 복구되는 트랜잭션 경계를 보장한다. 제품은 현재 카탈로그 정책을 따르며 신규 비즈니스 정책을 임의 도입하지 않는다.
- 실제 POST handler로 문제 payload 및 변형을 보내 4xx와 현금 불변·유한값·권한 불변을 검증한다. 정상 구매 성공, 잔액 부족, 저장 실패/중간 예외 회귀도 추가한다.

### R2-03 ETF 선택 직후 이전 종목 오주문
- 선택 ticker와 서버 stock ID/가격을 함께 검증하는 상태 계약을 사용한다. 종목 변경 즉시 이전 응답을 주문에 사용 불가능하게 하고 새 종목 로딩 중 매수/매도를 막는다.
- 취소/세대 번호 등으로 늦게 도착한 이전 응답 및 빠른 재선택 경합을 차단한다. 화면 ticker·표시 가격·API stock_id의 동일 자산을 보장한다.
- 실제 ETFPage React/JSDOM 클릭으로 KODEX200 로딩 후 SPY 전환, SPY 응답을 보류한 동안 주문 전송이 없어야 한다. 새 응답 이후에는 SPY ID/가격으로만 전송된다. 이전 응답 지연 도착 및 매도 경로도 검증한다.

### R2-04 잠금 대기 중 만기된 옵션 체결
- 실제 주문 변경/체결 commitGate 내부에서 최신 시각과 authoritative 계약으로 만기를 다시 검사한다. 함수 진입 시 캡처 nowMs를 확정 시각처럼 사용하지 않는다.
- 기존 nowMs/테스트 clock 주입 계약을 검토해 결정성을 유지하면서 현재 확정 시각을 주입 가능한 방식으로 보장한다. 잠금 대기 중 변할 수 있는 호가/권한/계약 조건도 필요한 범위에서 재검증한다.
- 실제 종목 락 Promise barrier를 이용해 만기 전 진입→대기 중 시간만 만기 후로 이동→락 해제 시 4xx 거절, 현금·보유·주문·예약 불변을 검증한다. 계약 날짜를 뒤늦게 바꾸어 시간차 검증을 대체하지 않는다. 기존 정상/동결/만기 배치 회귀 유지.

### R2-05 독립 engine-server build→start 기동 실패
- package.json/tsconfig/빌드 방식을 검토해 @/ alias가 실제 일반 Node 배포 산출물에서 해석되게 한다. 가능하면 기존 도구/정확한 빌드 변환을 활용하고 불필요한 의존성 추가는 피한다. 필요한 추가가 있으면 정당한 프로젝트 변경으로 수행하되 네트워크/권한 실패는 공식 escalation을 사용한다.
- 순수 tsx 테스트 통과로 완료 판정하지 않는다. 실제 build 명령 및 start와 동일한 일반 Node 방식으로 임시 빌드 산출물을 기동해 모듈 해석이 성공하고 전용 포트 health 응답까지 확인한다. 운영 스냅샷/포트와 분리한다.
- README 등 문서화된 build/start 진입점이 최종 구현과 일치하게 정리한다. 원격 배포는 하지 않는다.

### R2-06 마이페이지 USD 평가 환율 고정
- getUsdFxRateFromDb 호출에 맞는 {exchangeRates: ratesData} 구조 및 실제 API 응답 타입을 적용한다. 해외주식/USD ETF 평가, 손익, 총자산, 외화 현금이 동일 서버 환율을 사용해야 한다. 국내 KRW 자산은 유지한다.
- fallback은 실제 환율 부재에만 사용하고 타입이 any라 잘못된 호출이 숨지 않도록 한다.
- ratesData USD=2000에서 $100 자산이 200000원(138000원 아님)으로 계산됨을 검증한다. helper 단독만이 아니라 실제 MyPage 데이터 연결/렌더 또는 추출된 실제 사용 계산 경로를 확인한다.

### R2-07 환전 로그아웃/계정전환 잔액 잔존
- 인증 사용자와 결합된 잔액 상태, 즉시 초기화, 응답 취소/세대 검증으로 logout 및 A→B 전환 시 A 자산이 렌더링되지 않게 한다. 로그아웃 후 늦은 응답도 무시한다. 유효하지 않은 잔액/오류 응답도 안전하게 처리한다.
- 실제 Exchange 컴포넌트 React/JSDOM으로 로그인 잔액 로드→logout 렌더/효과→잔액 미표시를 검증한다. 미재현이었던 계정전환 지연 응답 경합도 이번에는 Promise barrier로 테스트한다. V2 래퍼 동일 동작 유지. 서버 타인 자산 공개 정책 변경 금지.
