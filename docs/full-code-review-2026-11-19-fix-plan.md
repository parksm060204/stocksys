## 항목별 수정 요건

1. F-01: trades 공개 projection과 필터/정렬/연산/카운트의 조합에서 민감 필드 추론을 차단한다. 내부 설정 읽기는 서버 권한으로 분리하고 실제 UI의 공개 필요 필드는 최소 안전 projection으로 제공한다. 인증된 본인 거래 조회는 세션/소유권 조건으로만 허용한다. 정상 공개 호가/체결 UI를 깨지 않게 실제 payload를 검증한다.
2. F-02: 채권의 호가·액면·거래수량·명시적 ISO 만기·쿠폰 주기를 일치시킨다. 상대 기간 2Y 문자열을 무작정 Date.parse하지 않는다. 만기 때 이미 지급한 쿠폰을 다시 연간 전액 지급하지 말고 지급 스케줄과 마지막 미지급분을 권위적으로 계산한다. 현재 사용자 채권 주문 미지원 상태와 저수준 정산 도달성을 구분하여 migration/정산 회귀 검증한다.
3. F-03~F-05: 옵션/채권 만기·이벤트 음수 비용 보상 등 모든 현금 credit이 부채 우선 상환을 일관 적용하도록 한다. 부채 발생 전 주문도 이후 추가 위험을 만들지 않게 주문 취소/거부/해제 현금 스윕 정책을 실제 주식/ETF/옵션/원자재 활성 경로에 적용한다. 예약금·부채·현금이 유실/중복 상환되지 않게 잠금과 롤백을 보장한다. 타 계좌/타 상품 동시 변경도 보호한다.
4. F-06: MarketEngine 전체 틱의 중간 상태와 autoSave/saveSnapshot/API가 같은 커밋 경계로 동기화되도록 한다. commitGate와 stock/account/tick 락 순서를 문서화하고 교착·재진입을 검증한다. 저장 실패 및 틱 내부 예외 시 disk/memory/runtime 불변식을 검증한다. 저장 콜백에 재진입하는 커밋 게이트도 고려한다.
5. F-07~F-08: built-in 참가자의 단일 metadata와 bot_type을 사용해 각 특화 풀을 실제로 초기화한다. 활성 설정과 기존 botsConfig 호환성을 유지한다. ASMarketMakerAgent가 읽는 orderBook의 실제 shape를 전달하고 부분체결 LP 주문이 새 slot과 이중 예약·잔존하지 않게 한 개의 권위 주문만 남긴다. LP upsert, 상한, STP와 가격시간 우선순위를 유지한다.
6. F-09~F-10: 구형 opt_c_720/opt_p_720의 STK/IDX 계약 의미와 프리미엄·행사가 단위가 일치하도록 정리한다. 과거 계약의 권리나 보유량을 임의로 재정의하지 않는다. 브라우저 OptionsPanel/optionBotEngine의 서버 권위 쓰기를 제거하고 필요한 기능은 인증·권한·잠금·영속화가 있는 서버 경로로 옮긴다. 클라이언트 import로 서버 코드가 유입되지 않게 검증한다.
7. F-11~F-14: profiles 조회에서 userId와 profileId index를 일치시킨다. 관리자/원자재 이벤트 런타임을 스냅샷/복원에 포함하고 list_stock 실패 시 marketIndex 등 모든 관련 맵/인덱스를 복구한다. standalone 자동 매칭도 할인/예약 수수료 정책을 공통 계산으로 적용한다. 옵션 엔타이틀먼트 정리는 락/commit gate/snapshot 내부에서 수행하고 추가 키까지 정확히 복원한다.
8. F-15/F-17/F-18: 실시간 서비스의 기본 시계는 실제 시간을 반영하고 시뮬레이션은 주입한 시계/PRNG로 결정론을 보장한다. Date.now/Math.random을 기계적으로 지워 고정 시간 서비스로 만들지 않는다. 주문/체결 ID는 재시작/실패 재시도/epoch와 동시 요청에 안전하게 생성한다. Quant/StatArb/CTA/CommercialHedger context 전달과 참가자 분류를 단일 metadata로 일치시킨다.
9. F-16.1~6 모두: OrderEntry의 실제 할인·예약·부채·최대 수량 계산을 서버 정책과 일치시킨다. shop의 보유/만료/패시브/판매중단과 loading 상태를 실제 프로필에 맞춘다. V2 ticker/bond 상세 접근, 원자재 전용 실제 호가창, 옵션 포인트·프리미엄 KRW 합계 및 채권 소수/액면 단위를 명확히 표시하고 데이터 연결을 실제 요청으로 검증한다.
10. F-19: 실제 in-memory/원격 모드 지원 범위를 확인하고 예제 설정·검증 스크립트를 활성 구현과 맞춘다. 비활성 legacy SQL을 최신 운영 스키마로 오인하지 않게 한다. HTTPS 제한을 임의로 완화하거나 보안 검사를 비활성화하지 않는다. 환경/스키마 검증은 유효한 불일치에 실패 exit를 반환하고 비활성 경로 경고를 구분하며 실제 비밀 env를 수정하지 않는다.

## 검증 및 완료 조건

- 각 하위 결함에 테스트/재현 조건을 연결한다. 돈·권한·저장·락/롤백·LP 중복에는 의미 있는 회귀 테스트를 남긴다. API 실제 payload 및 UI/서버 계약도 검증한다.
- 이전 실패/종료대기 8개 스크립트는 실제 현행 기능을 검증하도록 갱신한다. assert/보안 검증을 제거하거나 기대값을 완화해서 통과시키지 않는다. fixture/시그니처를 현행 계약에 맞추며 실제 cleanup으로 background timers를 종료한다. process.exit(0)로 미완료 비동기 작업/테스트 실패를 숨기지 않는다.
- 격리 STOCKSYS_DATA_DIR에서 root/engine tsc, lint, 새 회귀, 이전 핵심 회귀·Phase2~4·라우트·인증·전체 scripts/test 스위트를 수행한다. 장기 테스트는 충분한 maxBuffer/시간을 제공하고 결과를 회수한다. 관련 실패는 수정하고 진단 안 된 실패를 기존이라 단정하지 않는다.
- npm run build와 격리 next start HTTP smoke를 수행한다. 가능하면 실제 브라우저에서 옵션 주문/롤오버, 원자재 호가·청산·취소, 부채/상점/관리자/V2 경로를 확인하고 미실행 사항을 명시한다. 운영 OAuth/원격 DB/강제 종료 장애 주입은 사용자 승인 범위를 넘어 실행하지 않는다.
- docs/full-code-review-2026-11-19-fix-results.md에 원본 F-01~19 번호를 유지하고 F-16.1~6처럼 각 하위 결함별 해결/반증/미해결, 실제 파일·행, 정책·migration, 검증 명령/exit 및 범위 한계를 기록한다. 전체 해결 주장은 모든 필수 항목이 해결됐을 때만 한다.
