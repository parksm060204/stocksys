# 전체 코드 재리뷰 1회 — AGY Hydrogen 워커 지시서

## 요청과 역할

사용자 요청: "다시 한 번 루프를 돌아 전체 코드를 리뷰하고 결과를 공유해줘."

기존 역할 분담을 유지한다. AGY Antigravity Hydrogen이 실무 리뷰와 재현 검증을 수행하고 상위 Codex는 계획·지시·결과 검토와 사용자 보고를 담당한다. **이번 작업은 리뷰이며 애플리케이션 수정 요청이 아니다.** 발견된 문제를 조용히 수정하지 말고 현 상태와 재현 증거를 보고한다. 다른 워커를 추가로 만들지 않는다.

## 상태와 제약

- 현재 체크아웃의 staged/unstaged/untracked 변경을 모두 보존한다. 이전 수정 11건과 후속 A–F가 반영된 상태를 리뷰한다.
- AGENTS.md와 관련 로컬 Next.js 문서를 준수한다. 이전 완료 보고 및 테스트 통과는 검토 자료이지 정상성의 증명이 아니다.
- 앱 코드·기존 테스트·설정·데이터 파일을 수정하지 않는다. 영구 산출물은 `docs/full-code-rereview-findings.md`와 HISTORY.md의 append 기록뿐이다. 재현 스크립트가 필요하면 별도 임시 디렉터리에 두고 증거를 보고서에 재현 가능한 형태로 남긴다.
- 커밋/푸시/배포, 데이터 초기화, 프로세스 무단 종료, 기존 .data 읽기·덮어쓰기, 비밀값 출력 금지. 저장/재시작 검증은 격리 DB와 임시 STOCKSYS_DATA_DIR/ENGINE_SERVER_DATA_DIR를 사용한다.
- 실제 장애를 유발할 수 있는 무한 루프/대용량 테스트는 시간·메모리 제한이 있는 격리 자식 프로세스에서만 검증한다.

## 리뷰 범위

1. 디렉터리와 실행 진입점을 먼저 나열하여 범위표를 작성한다. `app`의 모든 API·페이지·훅/컴포넌트 연결, `lib`의 DB·인증·엔진·시뮬레이션·저장·리포지토리·옵션·원자재·상점·환전·rate limit, `engine-server`, 운영 설정·스크립트·테스트 구성의 주요 경로를 검토한다. archive/legacy는 현재 실행 여부를 구분한다.
2. 기존 리뷰 11건과 후속 A–F를 각각 현재 코드 경로에서 독립적으로 재확인한다. "이전에 수정했다"는 이유로 생략하지 않는다. 이번에 새로 도입된 서비스와 공통 commit gate/파일 락/원장 압축을 우선 살핀다.
3. 요청에서 DB/리포지토리, 정산, 저장, 응답, 브라우저 표시까지 이어지는 실제 경로를 추적한다. 단일 헬퍼 테스트 통과로 통합 동작을 가정하지 않는다.

### 집중 점검 항목

- **권한/정보 노출:** prod/dev guest 일치, OAuth 프로필 생성과 복원 순서, 관리자 권한, 프로필 허용 필드, 모든 RPC 화이트리스트, 세션의 실제 소유자 강제, 공개 원시 테이블/집계의 개인정보·미래 뉴스 노출, 유료 라이선스·만료의 서버 적용.
- **옵션:** 임의 가격 체결 방지, 실제 상대 주문/LP 자금·재고 보존, 미체결 주문의 현금·보유량 예약, 옵션끼리·주식끼리·원자재·환전·상점 사이 중복 소비, 만기/승수/손익/수수료 단위, 옵션 계좌 화면과 실제 holdings/order/trade/정산 일치. 휴면 주문의 수명과 취소 경로도 확인한다.
- **원자재:** 주문별 예약 ID 정확성, 부분 체결·자기매매·취소·만료·청산·포지션 반전, 손실/부채 보존, 동기 nextTick와 비동기 stepTickAsync 경로 혼용, 봇 장부와 사용자 장부 확정 순서, 실패 시 오더북/봇/가격/RNG/계좌 롤백 범위, 재시작 주문·잔량·예약 복원 및 고아 환불 중복 방지.
- **저장/동시성:** commit gate와 stock/account lock의 획득 순서 및 재진입 데드락, 큐 예외 후 회복, 저장 호출 시점/실제 serialization 시점, 다른 거래의 미확정 상태 노출, 저장 실패 후 응답·rollback·재시도, 웹 서버/별도 엔진 자동 체결의 durable commit, .lock 소유권/stale lock/정상·비정상 종료/두 프로세스 경합, HMR 및 다중 경로 모듈 싱글톤.
- **정산 멱등성/메모리:** 단조 ID watermark가 처리하지 않은 낮은 sequence 거래까지 거짓 중복으로 차단하는지, ID 파싱 신뢰·조작, custom ID archive가 실제로 무한 RAM 누적되는지, 원장·archive·epoch·시퀀스의 복원 완전성과 재시작 충돌, 거래 표시 cap과 권위 원장 보존 분리. 데이터 구조별 장기 실행 상한을 실제로 확인한다.
- **봇 자산:** 프로필/기관 포트폴리오/AgentAccount 중 권위가 하나인지, 재시작 시 AgentManager가 복원 자산을 초기값으로 덮어쓰는지, 별도 engine-server 재시작 컨텍스트/주문 ID/시뮬레이션 시간 복원, LP 부채/발행량 보존, 특정 봇의 음수/NaN·무한 증식·정산 누락.
- **수치:** 타입이 유효해도 곱셈·합산·반올림 후 Infinity/안전 정수 초과, 음수 잔액, 외화 최소 단위 왕복 환전 차익, 서버 rate 필드 일치, 30일 상품 기간과 실사용 적용, API body 제한과 동기 무제한 작업.
- **UI/연결:** 기본/v2의 실제 주문/구매/환전·계좌 갱신, 가짜 성공 표시, 구독/만료 권한 갱신, 폴링과 subscription cleanup, 브라우저/서버 경계 및 Next 현재 버전 API 사용.
- **테스트 신뢰성:** 새 테스트가 실제 API/repository/별도 프로세스 복원을 검증하는지, mutable 글로벌/자체 모킹/정적 문자열 검사로 결함을 숨기는지, assertions가 성공 경로만 확인하는지 검토한다.

## 검증 방식과 결과 신뢰도

- 모든 지적에 우선순위(P0/P1/P2/P3), 정확한 파일:라인, 구체적인 트리거와 영향, 최소 재현, 실제 관측 결과와 수정 방향을 적는다.
- 동적 재현 성공/코드 경로로 확인/환경 때문에 미검증을 구분한다. 추측만으로 결함으로 확정하지 않는다.
- 중요한 저장·동시성·멱등성 문제는 기존 테스트와 다른 경계값/호출 순서로 최소 재현한다. 재현이 불가능하면 그 이유와 필요한 조건을 명시한다.
- 루트/engine-server 타입 검사, build, ESLint와 기존 신규 검증 테스트 중 필요한 것을 실행한다. 이전 보고 숫자를 복사하지 말고 실제 이번 실행 결과를 기록한다. 테스트가 통과해도 코드로 확인된 결함을 무시하지 않는다.
- 검토하지 못한 영역과 외부 OAuth/다중 호스트 등 실제 제약을 별도로 적는다. "전체 코드"는 모든 분기의 완전 증명이라는 뜻으로 과장하지 않는다.

## 산출물과 완료 보고

- `docs/full-code-rereview-findings.md`: 요약, 검토 범위표, 심각도 순 발견 사항, 이전 11건/A–F 대응표, 실행한 검증과 결과, 미검증 범위.
- HISTORY.md에 실제 리뷰·재현·산출물 결과를 현재 로컬 타임스탬프로 append한다. 기존 기록은 수정하지 않는다.
- 상위 코디네이터에게 P1 이상 또는 재현 가능한 중대한 문제를 찾으면 중간 상태 메시지로 알려도 된다. 앱 코드는 수정하지 않는다.
- 완료 시 worker_done 보고에 발견 건수/심각도, 핵심 파일:라인, 동적 재현 여부, 테스트 결과, 보고서 경로를 포함한다. 결함 발견은 리뷰 업무 실패가 아니며, 리뷰와 보고서 작성이 끝났으면 작업 성공으로 보고한다.
