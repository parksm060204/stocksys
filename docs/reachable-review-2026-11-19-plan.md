# 실행 경로·재현 근거 중심 코드/보안 리뷰 (읽기 전용)

## 사용자의 현재 요청

현재 코드에서 실행 경로에 실제로 도달하는 재현 가능한 코드·보안 결함을 영역별로 리뷰하고, 각 항목에 영향, 발생 조건, 좁은 코드 위치와 검증 근거를 정리한다. 확인된 결함과 의심·미검증을 구분한다. 사용자가 워커로 수행하도록 명시했다. **수정 요청이 아니다. 코드를 수정하지 않는다.**

이전의 수정 지시와 무관한 새 읽기 전용 과제다. 이전 코드가 해결됐다고 가정하거나 이전 보고서의 숫자/결론을 되풀이하지 않는다. HEAD 7008f55뿐 아니라 현재 남아 있는 모든 미커밋 코드·신규 파일이 리뷰 대상이다.

## 리뷰 범위

1. **인증·인가·공개 데이터/API**: 세션/관리자/구독·본인 계좌 경계, local-db의 필터·정렬·join·RPC·카운트·오류 경로, 공개 데이터의 필터 오라클/우회, 범용 요청 파싱/입력 처리. 정상 사용자/비인증/비관리자가 실제 요청으로 접근 가능한지 구분한다.
2. **주문·금전·부채·정산**: 주식/ETF/옵션/원자재/채권/환전/상점/이벤트의 활성 경로, 양측 정산 및 누적/부분 체결, 승수·통화·수수료·예약, 부채 이전 주문·취소/환불·지급, user_id와 profileId, 부채 상환/총자산 일관성.
3. **동시성·영속성·실패 복구**: 각 엔진(localStandalone/ABM/engine-server)의 실제 시작 경로·락·커밋 게이트, autosave/매칭/API 경쟁, 저장 실패/재시도와 bot Runtime·난수·큐 복원, 외부 이벤트 공개 시점, 스냅샷 import와 rollback 구분, 인덱스 정합성, 재시작 ID/멱등성 및 장기 상한.
4. **시드·마이그레이션·파생**: 실제 계약 단위와 legacy 보유/미체결 권리, 채권 주기/기준일/최종 지급, 옵션 지수/승수·만기·기초가격, 모호한 데이터 차단이 다른 경로에서 우회되는지. 단순 저수준 임의 주입과 실제 시드·스냅샷/API 도달성을 분리한다.
5. **봇·시장·프론트엔드**: 실제 초기화된 봇만 검토하고 참여자·보유/FX·LP 슬롯·가격시간·자전거래·전략/매크로 경로를 추적한다. V1/V2/옵션·원자재·상점·뉴스·관리자 등 화면의 실제 request/response/조인·폴링·단위 및 오류 처리를 점검한다. 외부 소스 미연동/목업은 실제 사용자 영향이 확인된 경우만 결함으로 판정한다.
6. **운영·설정·검증**: 활성 모드/레거시 경계를 명확히 하고 데이터 cap·타이머·자원/로그·환경 fallback을 점검한다. 비활성 SQL 경고나 테스트 코드 단독 실패를 운영 보안 결함으로 부풀리지 않는다.

## 확정 결함의 엄격한 기준

- **진입점 → 조건 → 호출 경로 → 결함 위치 → 실제 관측 결과 → 영향**이 모두 연결된 경우만 확정 결함으로 올린다. 공격자/사용자 권한, 개발·프로덕션 구분, 어떤 실행모드인지 명시한다.
- 금전·보안·동시성 주요 주장은 격리된 실행 재현으로 확인한다. 소스 대조만 있는 경우에도 실제 API와 데이터 조건이 명확해야 하며 검증 수준을 `실행 재현` 또는 `정적 경로 확인`으로 구분한다. 후자는 실행 재현과 같은 수준으로 표현하지 않는다.
- 임의 상태를 직접 주입했을 때만 재현되는 문제는 그 상태를 실제 API/봇/저장 복원이 만들 수 있음을 추가 입증한다. 할 수 없으면 의심/미검증 항목으로 분류한다. outer rollback, CAS, 인증, 예약 검증 등 상위 보호가 반례를 막는지 반드시 확인한다.
- 재현 불가·유효성 불명인 이슈는 확정 항목 수에 포함하지 않는다. 단순 리팩터링/취향/설계 제안/운영 가정을 결함으로 쓰지 않는다. 개별 수정이 필요한 결함을 하나의 큰 그룹으로 묶지 않는다. 개수를 채우려 하지 않는다.
- P0는 무조건적·광범위 장애 또는 손실이 입증됐을 때만 쓴다. 조건부 문제는 조건과 영향에 맞는 우선순위를 부여한다.

## 실행 정체 예방

- 기존 워커의 장시간 대기가 반복됐으므로 `npx tsx` 일괄/inline 디버그 대기를 피한다. 로컬 설치 Node/tsx를 사용하고, 각 재현/테스트에 개별 출력 로그·명시적 제한시간을 둔다. 예: `node --import tsx <file>`를 spawnSync timeout/maxBuffer로 실행한다. 샌드박스에서 tsx 사용자 조회가 ENOMEM으로 실패하면 필요한 승인 흐름으로 재실행하고 테스트 결함으로 기록하지 않는다.
- 전수 회귀/빌드 반복이 목적이 아니다. 의심을 판별할 최소 관련 검증을 수행하고, 실패한 검사는 수정 없이 원인을 분류한다. 미완료 작업을 성공 종료 코드로 강제하지 않는다. 종료되지 않으면 제한시간·대기 핸들을 기록하고 해당 작업 소유 PID만 정리한다.
- 실행을 시작했다는 대기 문장만 남기지 말고 결과를 회수한다. 종료 시 반드시 worker_done을 보내고 보고서 경로·영역별 확정/미검증 수·주요 영향·실제 검사 결과를 보고한다. 이 과제의 성공은 읽기 전용 근거 보고서 완성이다. 결함/테스트 실패 발견 자체는 과제 실패가 아니다.
